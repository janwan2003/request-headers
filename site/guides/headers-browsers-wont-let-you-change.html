Which HTTP headers browsers won't let an extension change

Far fewer than the "forbidden header" lists suggest. Those lists limit page JavaScript, not extensions. In Chrome 159 and Firefox 158, HeaderDial's declarativeNetRequest rules set and removed Sec-Fetch-Site, Sec-Fetch-Mode, Sec-Fetch-Dest, Sec-Fetch-User, the Sec-CH-UA client hints, Origin, Referer, User-Agent and Accept-Encoding, and could set Cookie and even Host. What did not work: removing Host (both browsers), removing Connection (Chrome) or Priority (Firefox), and changing Content-Length or Transfer-Encoding, which broke the request. On responses, Firefox would not replace an existing Content-Type or Strict-Transport-Security value.

Page JavaScript versus an extension

The Fetch standard lists request headers a page's fetch() or XHR may not set: Host, Content-Length, Connection, Cookie, Origin, Referer, anything starting with Sec- or Proxy-, and more. We sent all of these from a page's fetch(). Both browsers dropped every one of them, so the server received the browser's own values. The exception was User-Agent: Firefox sent the page's value and Chrome did not. A custom header such as X-Custom went through in both.

Extensions are not bound by that list. Chrome documents the ModifyHeaderInfo rules it accepts, and MDN describes Firefox's implementation. Neither page lists the headers that are ignored after a rule has been accepted, which is why we measured it.

What the API accepts

Some rules are refused when the extension adds them. We called declarativeNetRequest.updateSessionRules directly to see where the two browsers differ:

HeaderDial turns append into set for request headers outside Chrome's list, with a message saying so, and refuses invalid names before the browser sees them. In Firefox, a set row with an empty value would make the browser reject the profile's whole rule. Since HeaderDial 0.3.1 that row alone is skipped, with a message under the editor, and the profile's other headers still apply (checked in Firefox 158.0.1). Fill in a value or switch the row to remove.

Steps: test a header yourself

  1. Click the HeaderDial icon. If the site-access banner appears, choose Allow on all sites or Only <current host>.
  2. Click + Request header (or + Response header), type the header name and a value you will recognise in a log, such as hd-test. Or choose remove.
  3. Open Where it applies, click + Only on…, choose Domain and enter a host whose logs you can read. A broken Content-Length rule on all sites breaks every form post.
  4. If the browser refuses the rule, the reason appears in the problems list under the profile.
  5. Load a page and look at what the server logged, or at an endpoint that echoes request headers. The DevTools Network panel shows what the browser meant to send. A server log shows what actually arrived.

The curl equivalent

Outside a browser nothing is forbidden, which is the main reason a server must not trust any of these headers:

curl -H "Host: admin.internal" http://203.0.113.10/
curl -H "Sec-Fetch-Site: same-origin" -H "Origin: https://app.example.com" -X POST https://app.example.com/api/transfer

Pitfalls

Fetch metadata (Sec-Fetch-*) and Origin protect users from other websites. A cross-site attacker cannot change them in a victim's browser. The user can, with an extension or curl, so they are no defence against the user. Never treat them as authentication.
  • HTTP/2 and HTTP/3 were not tested. We measured over HTTP/1.1. In HTTP/2, Host gives way to the :authority pseudo-header and connection-specific headers such as Connection and Transfer-Encoding are not allowed (RFC 9113), so results there may differ.
  • Removing is not the same as an empty value. Use remove to send no header. In Firefox an empty set is refused anyway.
  • Some removals are silently ignored. For Host, Connection in Chrome and Priority in Firefox, the rule was accepted and the browser sent its own value anyway. Check the server log rather than assuming a remove worked.
  • Switch it off afterwards. Give the row an expiry such as 15 min, or press Alt+Shift+D to pause every profile.

How to modify HTTP request headers in Firefox

Firefox has no setting for adding or changing arbitrary request headers on the pages you browse. Its DevTools can resend a single request with edited headers, but for anything lasting you need an add-on. HeaderDial for Firefox (Firefox 128 or later) adds, changes or removes request and response headers, limited to the sites you choose. It has the same profiles, filters, timers and import as the Chrome version, so a setup exported from Chrome works unchanged.

Install and requirements

Install HeaderDial on Firefox Add-ons. As of 20 November 2026 the listing is in review; if the link does not open yet, the review has not finished. HeaderDial needs desktop Firefox 128 or later, which includes Firefox ESR 128 and every release since.

If you want to run it from source in the meantime, clone the repository, run node scripts/build.js, open about:debugging, choose This Firefox, click Load Temporary Add-on… and select dist/firefox/manifest.json. Firefox removes temporary add-ons when it restarts.

Site access in Firefox

HeaderDial asks for no website access when you install it. The first time you open it, a banner says "HeaderDial needs your permission before it can change headers on websites" and offers two buttons:

  • Allow on all sites: headers can be changed anywhere your filters say.
  • Only <current host>: access for the site in the current tab only. You can add more sites later the same way.

Firefox then shows its own prompt to confirm. Until access is granted, HeaderDial's rules exist but change nothing, which is the behaviour our Firefox end-to-end test checks. If a page on one host calls an API on another, allow both hosts, or all sites. You can review or withdraw access later on HeaderDial's page in about:addons.

Firefox does not run add-ons in private windows unless you allow it. To change headers there, open HeaderDial's page in about:addons and set Run in Private Windows to Allow.

Steps

  1. Click the HeaderDial icon in the toolbar (it may be inside Firefox's Extensions menu until you pin it) and grant site access as described above.
  2. Click + Request header, type a name such as X-Debug and a value such as 1. Names like Authorization, Accept-Language and User-Agent are in the suggestions.
  3. Pick the operation: set replaces the value, append adds to it, remove drops the header. To change what the server sends back, use + Response header instead.
  4. Open Where it applies, click + Only on…, choose Domain and enter your host, for example staging.example.com.
  5. Reload the page. Open DevTools (F12), go to the Network panel, select a request and check its request headers.

The same features as in Chrome

The Firefox version is built from the same source files as the Chrome and Edge version; only the manifest differs. Everything works the same way:

  • Profiles with colours, each with its Active switch, and the global On/Paused switch. If two active profiles set the same header, the leftmost chip wins.
  • Filters: + Only on… and + Never on… with domains, URL patterns or regular expressions, request types, and Only in this tab (until it closes).
  • Timed headers: an expiry of 15 min, 1 hour, 8 hours or 1 day, after which the row switches itself off.
  • Import and export: Import… accepts a HeaderDial export, a HeaderDial share link or a ModHeader profile export, and Export all saves your profiles as JSON. To move from Chrome to Firefox, click Export all in Chrome and import the file in Firefox. See switching header extensions for the ModHeader case.
  • Share as link… in the ⋯ menu, which puts a profile into a link without uploading it anywhere.

The same append limit applies too: browsers let extensions append only to a short list of request headers, such as Accept-Language, Cache-Control and X-Forwarded-For. For other headers HeaderDial uses set and tells you so.

How it works in Firefox

HeaderDial uses Firefox's declarativeNetRequest API, the same API Chrome uses for Manifest V3 extensions. HeaderDial turns your profiles into a list of rules and hands it to Firefox; Firefox applies the rules to matching requests. The add-on never reads your traffic and makes no network requests of its own. In our tests in Firefox 158, rules added and removed headers on page loads and on fetch() calls, changed response headers that the page could read, and respected domain and regex filters.

Firefox's built-in alternatives

For some jobs you don't need an add-on:

  • Edit and Resend. In the DevTools Network panel, right-click a request and choose Edit and Resend. You can change the URL, method, headers and body and send it once. The response appears in the Network panel; the page itself does not change. This is the quickest way to test a single API call.
  • Language. Settings › General › Language › Choose sets the list Firefox sends in Accept-Language for every site. See testing Accept-Language for a per-site approach.
  • User-Agent. Responsive Design Mode accepts a custom user agent for the current tab, and the general.useragent.override preference in about:config changes it everywhere.

None of these can add a header such as Authorization to every request a page makes, limit it to one host or switch it off on a timer. That is what an add-on is for.

The curl equivalent

curl -H "X-Debug: 1" https://staging.example.com/

In the Network panel, right-click a request and use Copy as cURL to get the full command with every header Firefox sent.

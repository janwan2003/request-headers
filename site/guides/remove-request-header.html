How to remove a request header in Chrome

To stop Chrome or Edge from sending a particular request header, add a row for that header in HeaderDial and set its operation to remove. Matching requests then go out without it. This is how you test what a server does when Cookie, Referer, Accept-Language or any other header is missing, without clearing browser data or changing settings.

Headers people commonly remove

HeaderWhy remove it
CookieSee a page as a logged-out visitor without logging out in other tabs; check that an endpoint really requires a session.
RefererTest hotlink protection, referrer-based analytics, or code paths that assume a referrer is present.
Accept-LanguageSee which language the server falls back to when the browser expresses no preference.
If-None-Match, If-Modified-SinceForce full responses instead of 304 Not Modified while debugging caching.
AuthorizationCheck that an API returns 401, not data, when no credentials arrive.

Steps

  1. Click the HeaderDial icon to open the popup. If the site-access banner appears, choose Allow on all sites or Only <current host>; without it the browser won't let an extension change any headers.
  2. Click + Request header and type the header name, for example Referer. Suggestions appear as you type.
  3. In the operation select, choose remove. The value is not used for this operation, so you can leave it empty.
  4. Open Where it applies and click + Only on <current host>, or + Only on… for another domain. Without a filter the header is removed on every site.
  5. To remove it only for certain kinds of requests, tick request types. With none ticked the rule covers all of them, including page loads.
  6. Reload the page and check the result (see below).

Several rows can be combined in one profile, for example removing both Cookie and Authorization to simulate an anonymous client. To undo the change, untick the row's enabled checkbox, switch the profile off, or click × to delete the row.

Check that it worked

The footer of the popup shows "Applied to N requests in this tab", which confirms the rule matched. To see what the server received, request a URL that echoes the request headers back, such as a small endpoint on your own server, or look at your server's request logs. The DevTools Network panel also lists request headers for each request.

The curl equivalent

curl only sends a few headers by default. To drop one it adds itself, pass the name with nothing after the colon:

# send no User-Agent and no Accept header
curl -H "User-Agent:" -H "Accept:" https://www.example.com/

# curl sends no Cookie or Referer unless you ask, so simply omit -b and -e
curl https://www.example.com/

To copy a real browser request and then delete headers from it, use Copy as cURL in the DevTools Network panel's context menu and remove the -H lines you don't want.

Other ways to drop Referer

If you control the page, you don't need an extension to stop the referrer: send Referrer-Policy: no-referrer, add <meta name="referrer" content="no-referrer">, or put rel="noreferrer" on individual links. A header rule is useful when you are testing someone else's page, or want to see the server-side effect without deploying.

Pitfalls

Removing Cookie affects every matching request, including the ones that keep you logged in. Scope it with a filter or the Only in this tab (until it closes) checkbox, and give the row an expiry such as 15 min if you only need it briefly.
  • Use remove, not an empty value. remove drops the header entirely. A missing header and a header with an empty value are different things to most servers, so pick the operation that matches the case you want to test.
  • A higher-priority profile can put it back. If another active profile sets the same header, the leftmost profile chip wins. Reorder with Move left (higher priority) in the ⋯ menu.
  • Cached responses. A response from the browser cache never reaches the server, so the removal seems to have no effect. Tick "Disable cache" in the Network panel while testing.
  • Responses are separate. To strip a header the server sends, such as Set-Cookie or Content-Security-Policy, use + Response header instead.
